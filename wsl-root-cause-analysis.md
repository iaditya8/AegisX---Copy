# AegisX WSL Root Cause Analysis (INFRA-01)

## Findings

1. **Missing virtual disk file (`ext4.vhdx`)**: The registration for the WSL2 Ubuntu distribution existed in the Windows registry, but the physical storage disk was absent.
2. **UAC / Service Startup Block**: Running `Start-Service -Name "com.docker.service"` failed due to lack of administrative privileges (access denied to start Windows service).
3. **Mismatched Docker Compose credentials**: The `DATABASE_URL` in `docker-compose.yml` specified user `aegisx_user` and password `aegisx_password`, but the Postgres container initialized with `POSTGRES_USER=postgres` and `POSTGRES_PASSWORD=postgres`, blocking API connections.
4. **Missing table existence checks in Alembic migrations**: Migration `7476d4d6195a_crit_07_rls_hardening.py` failed because it tried to manipulate the `recovery_objectives` table which had not yet been created by the migration sequence.
5. **Database Transaction Ordering / SQLAlchemy Session Flush Mismatch**: Celery task executions suffered from `ForeignKeyViolationError`s during cache bootstrapping because dependent children objects (`RecoveryObjective`, `CyberResilienceHistory`, `SOCAnalyticsHistory`, etc.) were flushed to the database before their parents were assigned primary keys or inserted.
6. **Event Loop Mismatch inside Celery Worker**: Celery task runner reused database connection pools across different task event loops, throwing `RuntimeError: Task got Future attached to a different loop`.
